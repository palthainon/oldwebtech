## Behavior

- In an adaptive product effort, use the roadmap to communicate the product's current direction and planned functionality to stakeholders. Use that roadmap as the starting point for release planning: group and sequence the components or features intended for each release, then refine them into the release backlog.

## Defaults or baseline

- A product roadmap represents the current plan and can evolve as organizational needs and priorities change. Release planning adds detail about which features are grouped into each release; iteration planning selects backlog items for upcoming iterations.

## Gotchas

- Treating every distant roadmap item as a fixed delivery promise can set expectations that all planned capabilities will ship before new ones are considered. PMI's agile planning guidance cautions against planning too many releases far in advance; recheck the roadmap and release sequence as priorities change.

## Verify

- For the scenario's current priorities, map candidate components to the intended releases and check that the release sequence remains consistent with the roadmap. Then distinguish that release grouping from assigning backlog items to a particular iteration.

## Applies to

- CAPM Domain 4, Task 4 (explain a product roadmap's application and determine which components go to which releases).
