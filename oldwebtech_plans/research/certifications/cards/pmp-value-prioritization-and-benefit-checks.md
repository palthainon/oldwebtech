## Behavior

- When stakeholder feedback changes which deliverable is expected to create the most value, revisit the work priority with those stakeholders and check that the intended benefit can be measured. A smaller delivery may be considered if it realizes useful value sooner; the outline makes that an opportunity to assess, not a rule to split every deliverable.

## Defaults or baseline

- PMI's outline calls for value assessment and benefit measurement, but does not prescribe one universal metric or prioritization method. The project's intended benefits and stakeholder context determine what to track; this is a bounded application of the outline, not an issuer-mandated metric.

## Gotchas

- Treating the initial priority order as fixed can overlook new stakeholder feedback. Completing outputs alone does not show whether the intended benefit was realized; the project needs a way to measure that result.

## Verify

- For a scenario with a changing priority or a proposed smaller release, read Process Task 3's enablers on stakeholder feedback, incremental value, ongoing value checks, and benefit measurement. Confirm the scenario's measure against its stated benefit; the outline does not define a universal metric.
