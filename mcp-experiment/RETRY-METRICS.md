# Estimated validation retries

The Workbook uses infra/validation-retries.kql. No server instrumentation changed. The query uses existing pseudonymous caller fingerprints, timestamps, endpoint names, known tool names, and outcomes. It returns aggregate counts only. Do not save fingerprints, arguments, unknown tool names, field values, or error bodies.

Each validation error anchors one transition. Match only the next call from the same caller group to the same endpoint and known tool within ten minutes. A matching success is a successful retry estimate. Another validation error is an invalid retry. Other outcomes remain separate. A repeated error can anchor its own next transition; this metric counts transitions, not tasks or sessions. Unknown tools or absent fingerprints are unmatchable. Equal-time events in a group are ambiguous. Missing events can produce false matches.

Exclude marked internal requests and all groups seen in marked tests across available retained telemetry. This can remove real users behind shared networks. Changing fingerprints can hide retries. Unmarked operator traffic can remain. A matched success does not prove the caller used repair guidance.

Allow five minutes for ingestion. Allow ten additional minutes for each error to receive a retry. New errors remain pending. Show successful retries divided by eligible mature errors, and separately by observed retries. Always show denominators. A zero denominator has no percentage. No observed retry does not mean the client abandoned its task.

For weekly reviews, convert the previous seven complete Eastern dates to UTC bounds. Set cohortStart to the interval start and cohortEnd to its exclusive end. Read calls through cohortEnd plus ten minutes for matching. Before filtering validation error rows, retain those successor calls. Filter error timestamps to the report interval. Keep pending tail errors separate when observation time cannot cover their full window. Keep the test-caller lookup across all retained data, not only the weekly cohort. Count each error only in its own week. Do not add overlapping cumulative snapshots to weekly totals.

Raw telemetry expires after 60 days. Historical test exclusions and retry matching become incomplete as events expire. Archive weekly aggregates with interval bounds, query text, exclusions, observation cutoff, and completeness flags. Flag delayed ingestion, telemetry gaps, caps, outages, and missing history. Compare pre-release and post-release cohorts only with a verified traffic-promotion timestamp. Deployment start is not promotion. A comparison cannot establish causality.

The October 19 initial snapshot found ten eligible external-like validation errors with no observed next call within ten minutes. Twelve unknown-tool errors were unmatchable. These historical counts do not measure the effect of the newly deployed repair guidance.
